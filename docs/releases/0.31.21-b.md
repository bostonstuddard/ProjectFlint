# Project Flint 0.31.21-b

## Intent
Restore Java 21 compilation after the v0.31.20-b advancement-retirement patch left an extra closing brace in the no-op `ModAdvancements` compatibility shim.

## Player-facing behavior
No gameplay behavior changes. Minecraft advancements remain fully disabled, Flint Quests remains the replacement progression path, and all v0.31.20-b gameplay changes are preserved.

## Architecture
`ModAdvancements` remains as a tiny source-compatibility bridge because many legacy call sites still reference `awardAll(...)` and `award(...)`. Both methods intentionally do nothing. This hotfix only restores a valid Java class structure around those no-op methods.

## Design reasoning
Removing every legacy call site in the same release would create a large unrelated diff and increase regression risk. Keeping one valid no-op compatibility class lets Project Flint remain advancement-free while Flint Quests hooks replace the old progression calls incrementally.

## Tuning snapshot
No tuning changes from v0.31.20-b.

## Assets and licenses
No assets were added or changed.

## Known limitations
Legacy Java classes still call `ModAdvancements`, but those calls have no gameplay effect. They can be removed as Flint Quests custom-event coverage expands.

## Validation
The release validator confirms the expected version, advancement resources remain absent, and the compatibility shim contains exactly one valid class declaration with both no-op methods. The malformed v0.31.20-b brace pattern is explicitly rejected.

## Next release pressure
Continue replacing legacy advancement-only calls with Flint Quests custom events where bespoke Project Flint mechanics need quest tracking.
