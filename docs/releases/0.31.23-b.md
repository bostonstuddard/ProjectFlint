# Project Flint 0.31.23-b — External PF-EMI Runtime

## Intent
Make the separately built PF-EMI jar authoritative at runtime. Project Flint must not ship an older nested `emi` mod that competes with the standalone PF-EMI build in the player's `mods` folder.

## Player-facing behavior
Players install two jars beside each other: the Project Flint jar and `PF-EMI-1.21.11.jar`. Replacing PF-EMI with a newer compatible build changes the EMI implementation Project Flint uses without requiring Project Flint itself to be rebuilt. No gameplay mechanics changed in this release.

## Architecture
`fabric.mod.json` continues to declare an `emi` dependency and the Project Flint EMI plugin entrypoint. `build.gradle` resolves `libs/PF-EMI-1.21.11.jar` through `modCompileOnly` only so Project Flint's EMI compatibility source can compile/remap against the EMI API. There is no Loom `include` declaration, so PF-EMI is never copied into `META-INF/jars` or added as nested Fabric metadata.

## Design reasoning
Fabric resolves mods by mod ID. PF-EMI intentionally keeps the standard `emi` ID, so shipping one `emi` nested inside Project Flint while also placing another `emi` jar in `mods` makes independent PF-EMI development unreliable. A single external runtime installation avoids duplicate-ID resolution and lets PF-EMI iterate on its own release cycle.

## Tuning snapshot
No balance values changed. Project Flint still requires an `emi` provider at runtime and still registers `dev.projectflint.compat.emi.ProjectFlintEmiPlugin`.

## Assets and licenses
No assets were added or modified. PF-EMI remains a separate jar/project and is not redistributed inside the Project Flint binary by this build.

## Advancement coverage
Minecraft/Project Flint advancements remain disabled. Flint Quests remains the progression replacement path.

## Known limitations
The Project Flint source tree still needs a compatible `libs/PF-EMI-1.21.11.jar` while compiling because the EMI plugin imports EMI API classes. That local jar is a build input only. A normal game installation must provide PF-EMI separately in the `mods` folder.

## Validation
The release validator requires `modCompileOnly` PF-EMI wiring, rejects every PF-EMI `include`/nested declaration, verifies the external `emi` dependency, and checks the local compile-time jar metadata when present. `build.bat` also inspects the finished Project Flint jar and fails the build if a nested `PF-EMI-1.21.11.jar` is found.

## Next release pressure
Keep the Project Flint EMI integration on stable/public EMI APIs so PF-EMI can continue evolving independently without forcing Project Flint rebuilds.
