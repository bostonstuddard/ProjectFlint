# Project Flint v0.28.7.3-a

## Intent
Correct five playtest failures left after v0.28.7.2-a without retuning unrelated progression: Brown Bear model mapping, full-night fog presentation/range, accidental coupling between the worldgen Loose Rock and held Rock art, bear combat threat, and Loose Soil multitool mining permission.

## Player-facing behavior
- Brown Bears now render through the same canonical vanilla Polar Bear model geometry/layers used by Black Bears. The incorrect custom Brown Bear mouth UV remap is removed.
- At full night outdoors, atmospheric fog now begins at **6 blocks** and reaches full density at **8 blocks**. The fog color transitions toward **black** as night reaches full strength instead of creating a white wall around the player.
- The naturally generated Loose Rock is treated as its own world block visual. Its block model no longer references the held Rock/Loose Rock sprite or the `block/placed/rock` mirror used by physical assemblies/stockpiles.
- Black Bear max health is **22.5** and attack damage is **6.0**. Brown Bear max health is **27.5** and attack damage is **7.0**. Both receive **+1.25 blocks** of additional horizontal melee reach.
- Loose Soil can now actually be mined with Project Flint multitools. It is admitted through the same primitive attack/break authority checks as Dirt and uses the same multitool destroy-progress formula.

## Architecture
- Brown Bear rendering no longer owns a custom model-layer definition. `BrownBearRenderer` bakes `ModelLayers.POLAR_BEAR` / `POLAR_BEAR_BABY`, removing an unnecessary divergence from Minecraft's expected 128x64 Polar Bear UV layout.
- `ProjectFlintNightFogEnvironment` owns both the Project Flint full-night distance envelope and its base fog color. Distance and color therefore strengthen from the same `nightStrength` value.
- The three stone concepts remain intentionally separate resource paths:
  - worldgen Loose Rock: `blockstates/loose_rock.json` -> `models/block/loose_rock.json`;
  - held Rock/Loose Rock: `items/loose_rock.json` -> `models/item/rock.json`;
  - player Rock Stockpile: `blockstates/rock_pile.json` -> `models/block/rock_pile_*.json`.
- Primitive mining is deny-by-default, so a custom block requires both destroy-progress permission and admission through the primitive interaction authority gates. Loose Soil now satisfies both halves of that contract.

## Design reasoning
- A 1-to-8-block fog ramp made most of the scene opaque within only a few blocks even though the requested maximum visibility was approximately eight. Starting the ramp at six gives a readable six-block core and an eight-block fade boundary.
- Black fog is required for true night darkness; a bright atmospheric fog color defeats the intended darkness even when the lightmap itself is dark.
- The worldgen Loose Rock is not the held Rock item and should never inherit its sprite merely because both ultimately yield/use Rock gameplay resources.
- Bears have large bodies, so vanilla polar-bear melee reach was too easy to exploit by standing just outside the hit check. Expanding their attack bounding box makes their visible body size better match their threat range.
- Loose Soil's earlier speed fix was insufficient because `PrimitiveInteractionSystem` still denied the attack before the destroy-progress path could matter.

## Tuning snapshot
- Full-night fog start: **6.0 blocks**.
- Full-night fog end: **8.0 blocks**.
- Full-night fog target color: **black**.
- Black Bear max health: **22.5** (25% above 18.0).
- Black Bear attack damage: **6.0** (+2).
- Brown Bear max health: **27.5** (25% above 22.0).
- Brown Bear attack damage: **7.0** (+2).
- Bear additional horizontal melee reach: **1.25 blocks**.
- Loose Soil multitool progress: same shared formula used by Dirt/Grass/Gravel earth-mining targets.

## Assets and licenses
- No texture PNG was edited, recolored, resized, cropped, composited, or regenerated.
- `brown_bear.png`, `black_bear.png`, and the held Rock item texture remain byte-for-byte unchanged.
- The worldgen Loose Rock block uses Minecraft's loaded `minecraft:block/stone` block texture through its own block model, keeping it independent from the held Rock sprite while remaining resource-pack-aware.

## Advancement coverage
No new progression capability was introduced. These are rendering, balance, and permission corrections to existing systems, so no advancement was added.

## Known limitations
- The exact final bespoke worldgen Loose Rock artwork remains an asset-direction task; this hotfix deliberately prioritizes keeping the world block separate from held-item art and uses the native block stone surface instead of inventing or modifying texture pixels.
- Client visual validation of the Brown Bear model and night fog still requires the local Minecraft playtest.

## Validation
- All JSON resources parse successfully.
- The release validator checks that the worldgen Loose Rock references `minecraft:block/stone` and that the held Loose Rock item still resolves separately to `projectflint:item/rock`.
- The validator checks the 6-to-8-block night fog envelope and black fog-color interpolation.
- The validator checks Brown Bear custom model removal, canonical model-layer usage, exact bear health/damage values, and extra melee reach.
- The validator checks Loose Soil in both multitool authority lists and the shared destroy-progress branch.
- Changed Java sources were compile-checked against the uploaded mapped Minecraft 1.21.11/Fabric development cache where available; local `build.bat` remains the final full Fabric build/client gate.

## Next release pressure
Retest the exact five reported cases only: Brown Bear face/body mapping, midnight fog color and 6–8-block visibility, fresh-world generated Loose Rocks, bear melee engagement distance, and Loose Soil mining with each multitool tier.
