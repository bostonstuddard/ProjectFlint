# Project Flint v0.31.29-b

## Intent
Expose the Chicken Nest as a real small container, make its claimed/occupied state visible to the player, close the visual hole through the Nest floor, and add a reusable fired-clay water vessel without disturbing the established chicken, kiln, grinder, or water-system rules.

## Player-facing behavior
- Right-clicking a Chicken Nest opens a GUI with four one-egg storage slots and the player inventory.
- The Nest GUI shows `Occupant: Chicken` when the Nest has its established chicken owner and `Occupant: None` otherwise.
- Eggs can be moved in or out through the normal inventory interface; breaking the Nest drops all stored eggs.
- The center of the Nest now has a one-pixel-thick hay floor, so the support block below is no longer visible through the model.
- The Wooden Grinder now converts 3 vanilla Clay Balls + 1 existing Woven Chest Frame into 1 Unfired Clay Bucket.
- Firing the Unfired Clay Bucket through the normal Project Flint kiln-processing path produces a Clay Bucket.
- A Clay Bucket collects one full water source block, becomes Clay Bucket (Water), places that water using normal water-bucket behavior, and returns the empty Clay Bucket.
- Clay Buckets cannot collect lava or any other non-water fluid.

## Architecture
`NestBlockEntity` is now a four-slot `RandomizableContainerBlockEntity`; ownership remains the same persistent chicken UUID used by `ChickenNestSystem`. `NestMenu` synchronizes the owner-presence state through `ContainerData`, and `NestScreen` renders the storage/player slots plus the occupant label. The block opens that menu and uses normal container-content dropping when destroyed.

The clay vessel is split into an empty `ClayBucketItem` and a filled `ClayWaterBucketItem`. The empty item performs a source-water-only pickup check before invoking the target block's bucket-pickup behavior. The filled item delegates water placement to vanilla `BucketItem` behavior and substitutes the returned vanilla bucket with the Project Flint Clay Bucket. Project Flint gameplay registries remain authoritative; PF-EMI remains presentation-only and external.

## Design reasoning
The Nest already had persistent ownership and a four-egg capacity, so exposing those four units as four one-item slots makes the state understandable without changing chicken behavior. Showing ownership in the GUI answers whether the Nest is claimed without introducing a second occupancy system.

For the new bucket, the existing `WOVEN_CHEST_FRAME` is used as the requested woven frame because it is the current Project Flint woven-frame item. Requiring firing keeps the vessel inside the established clay-processing progression. Source-water-only pickup deliberately prevents the clay vessel from becoming a lava bucket while still making it a full one-bucket water transport upgrade over the half-bucket Water Bearing Pot.

## Tuning snapshot
- Chicken Nest storage: 4 slots, maximum 1 Egg per slot.
- Chicken Nest ownership/search rules: unchanged; first successful laying chicken owns the Nest and the established 10-block search radius remains.
- Clay Bucket grinder input: 3 Clay Balls + 1 Woven Chest Frame.
- Clay Bucket firing time: existing kiln meat/fired-mold baseline (`GameplayTuning.KILN_MEAT_COOK_TICKS`).
- Clay Bucket capacity: 1 full water source block.
- Lava capacity: none.

## Assets and licenses
The three Clay Bucket item sprites are deterministic derivatives of Minecraft 1.21.11's vanilla bucket/water-bucket silhouettes using colors sampled from existing Project Flint Unfired Clay Ball and Clay Pot textures. No generative image system was used. Exact source paths, transformations, and SHA-256 hashes are recorded in `docs/TEXTURE_PROVENANCE.md` and `docs/texture_provenance.json`. The Nest floor uses Minecraft's existing hay-block textures through its block model.

## Advancement coverage
Minecraft advancement progression remains intentionally disabled. This release does not restore or add advancement JSONs; Flint Quests remains the progression/integration direction.

## Known limitations
The Nest's occupant label reflects the established persistent owner UUID rather than adding live chicken-presence tracking, so it is intentionally equivalent to “this Nest is claimed.” The Clay Bucket supports Project Flint's requested water use only; lava and other bucket fluids are rejected.

## Validation
The release validator checks the four-slot Nest container/menu/screen registration, occupant synchronization, hay floor model, grinder/firing registrations, source-water-only Clay Bucket behavior, item resources/translations, texture hashes, version/build wiring, and the existing PF-EMI external-ownership boundary. Targeted Java 21 compilation checks were run against the available Minecraft/Fabric classes for the new bucket and Nest implementation. A full Gradle build remains unavailable in this environment because Fabric Loom 1.14.10 is missing from the offline plugin cache, so no successful full Gradle compilation is claimed here.

## Next release pressure
Runtime-test the Nest GUI and Clay Bucket in the normal Windows development environment, especially shift-click slot behavior, ownership-state refresh while a menu is open, source-water pickup/placement, and interaction with Project Flint's non-infinite-water rules.
