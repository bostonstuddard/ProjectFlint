# Project Flint v0.31.50-b — Hardwood Crafting Table timing repair

## Intent
Restore the intended three-second, per-craft Hardwood Table delay without the instant-output client/server mismatch of the earlier workstation.

## Player-facing behavior
- The Hardwood Crafting Table uses the familiar 3×3 worktable layout. When a valid recipe is arranged, the recipe takes **3 seconds (60 server ticks)** to process.
- A small progress bar and countdown below the output slot show when the result will become available; the finished item appears **only after processing completes**.
- Altering any ingredient during processing cancels and restarts the timer; invalid recipes show no output.
- Taking one result starts a **new** three-second cycle. Shift-click collects only the one available result and cannot instantly mass-craft a stack. Result slot hotbar swaps cannot skip the timer.
- The normal rules for ingredient consumption, tools, and reusable containers still apply. Closing the table returns the ingredients as before. The table remains movable.

## Architecture

### Technical diagnosis and fix
Previous versions opened a `CraftingMenu` on the client (instant recipe outputs) but installed a `mayPickup` delay only on the server. This produced immediate-looking results, a missing countdown, failed clicks and inconsistent shift-click behavior. It could also reset the cooldown in response to unrelated slot updates.

The Hardwood Table now has a dedicated menu type and a matching client screen. The server computes valid vanilla crafting recipes directly from the actual 3×3 input, withholds the result while pending, and synchronizes both the output and a 0–60 progress data slot. Reopening the table or changing inputs starts fresh processing. The vanilla `ResultSlot` still handles recipe results, ingredient returns and achievements.

## Design reasoning
Player inventory changes must never produce a crafting result before time expires; using server-authoritative output synchronization prevents both accidental instant crafts and misleading visual results. Existing vanilla crafting recipes and ingredient consumption remain unchanged.

## Tuning snapshot
- Crafting time: **60 server ticks / 3 seconds**, with a new cycle for each output.
- Progress: shown in the GUI below the result slot.
- Invalid recipes: no progress and no result.
- Input edits: reset processing.

## Assets and licenses
No new artwork or external content added. Vanilla crafting-table GUI texture and existing Project Flint assets are used.

## Advancement coverage
No gameplay quest ownership changes. Flint Quests remains the progression owner; Project Flint does not register EMI recipes.

## Known limitations
Full Gradle build and live Minecraft client/server tests are not available in this environment; GUI runtime and real multiplayer interactions require playtesting.

## Validation
1. Put a valid recipe in the empty table; verify no item is visible or collectible until three seconds have elapsed. Progress rises from zero to full.
2. Change a single ingredient mid-timer; verify the prior result stays unavailable, and that a new valid recipe starts a fresh three-second timer.
3. Arrange enough materials for several identical crafts and shift-click the output; verify only the one ready craft is transferred and that the next output waits three seconds.
4. Test left/right pickup, hotbar-swap and invalid recipes; no instant crafting or ghost result should appear.
5. Test a recipe with a reusable ingredient (including a container remainder) and confirm the remainder is returned without an extra or missing item.
6. Close the table before the timer finishes; reopen and verify ingredients are returned as usual and the processing timer resets.
7. Reposition the block and use it in survival and creative, including multiplayer, to confirm server authority.

## Next release pressure
Verify timer synchronization, remainder handling and shift-click behavior on a live Minecraft client and dedicated server.

## Scope and validation
Only the Hardwood Table menu, client screen, registration and release files are modified. Other crafting stations and tools are unchanged. Source classes were compiled in isolation against Minecraft 1.21.11 mapped classes and dependency stubs; a complete Gradle build and in-game playtest remain unverified.
