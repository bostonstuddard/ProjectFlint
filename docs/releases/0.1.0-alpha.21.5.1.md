# Project Flint 0.1.0-alpha.21.5.1 — Minecraft 1.21.11 Rotation/Phantom Compile Hotfix

## Intent

This is a compile-only compatibility correction for the alpha.21.5 placement/phantom patch. It does not retune or reinterpret any gameplay behavior.

## Player-facing behavior

- Crude kilns still rotate to face the placing player.
- Crude kilns still require a sturdy supporting block below.
- Phantom spawning remains disabled by default.
- No texture, model, recipe, timing, yield, durability, or progression behavior changed.

## Architecture

`HorizontalDirectionalBlock.FACING` is declared by the current Minecraft 1.21.11 Mojang-mapped classes as `EnumProperty<Direction>`, so the crude kiln now uses that exact mapped type instead of the nonexistent `DirectionProperty`.

The phantom default is applied through the Overworld `ServerLevel` gamerules using `net.minecraft.world.level.gamerules.GameRules` and `GameRules.SPAWN_PHANTOMS`.

## Design reasoning

The alpha.21.5 intent was already correct; only the mapped API names were wrong. This hotfix therefore changes the smallest possible surface area and preserves the already-approved placement and phantom behavior.

## Tuning snapshot

No tuning values changed in alpha.21.5.1.

## Assets and licenses

No texture or other art asset changed in this hotfix. The strict human-made texture policy and alpha.21.4 provenance ledger remain unchanged.

## Advancement coverage

No advancement logic or advancement JSON changed in this hotfix.

## Validation

The corrected symbols/signatures were verified directly against the cached Minecraft 1.21.11 Mojang-mapped jar used by the Project Flint workspace:

- `HorizontalDirectionalBlock.FACING` → `EnumProperty<Direction>`;
- `GameRules` → `net.minecraft.world.level.gamerules.GameRules`;
- phantom gamerule → `GameRules.SPAWN_PHANTOMS`;
- gamerule access → `ServerLevel#getGameRules()`.

The Project Flint static release validator also checks the exact corrected API strings.

A full Gradle build cannot be executed in the artifact environment because Fabric Loom 1.14.10 cannot be resolved by the local plugin resolver. The supplied local build log shows that the user's machine resolves Loom correctly, so this environment limitation is separate from the reported Java compilation failure.

## Known limitations

The deprecation warning in `SuperHeatedClayItem` is unchanged because it is a warning, not one of the compile errors reported in this build failure.

## Next release pressure

- Re-run the local Windows build with this hotfix applied.
- If another compiler error appears, patch only the newly reported 1.21.11 API mismatch rather than altering unrelated gameplay or assets.
