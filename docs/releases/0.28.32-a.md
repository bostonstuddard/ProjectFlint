# Project Flint v0.28.32-a — Lumber Processor Chop Prediction Hotfix

## Intent
Make a correctly formed, fully watered Lumber Processor reliably start its Flint Plant Cutter chopping stage instead of appearing completely unmineable.

## Player-facing behavior
A stripped Overworld log placed directly on the Chopping Block now shows the intended 7.5-second breaking progress whenever Flint Plant Cutters are held. If the server finds the processor invalid or the Water Pot underfilled, the operation still cannot complete and the existing action-bar guidance remains authoritative.

## Architecture
Minecraft predicts destroy progress client-side, but the Lumber Processor's Water Pot and controller state live in server-authoritative block entities. Client-side attack/progress paths therefore no longer query full `isValidProcessor`/`hasFullWater` state. Server-side `canChop()` and `startWash()` still perform the complete validation before the staged log is consumed.

## Design reasoning
The client only needs enough information to animate the attempted chop. Letting unsynchronized block-entity data decide whether mining can even begin creates false negatives like a visibly full 1.0-bucket Water Pot producing zero progress. Authority remains on the server so this does not create a bypass.

## Tuning snapshot
- Chopping: 150 ticks / 7.5 seconds.
- Washing: 200 ticks / 10 seconds.
- Water requirement: 1.0 bucket.
- Required tool: Flint Plant Cutters.

## Assets and licenses
No asset changes in this hotfix.

## Advancement coverage
No advancement changes. The existing Lumber Processor and washing advancements remain intact.

## Known limitations
The client can begin showing chop progress even if the server will reject an invalid/empty processor; the server then cancels completion and displays the relevant requirement. This is intentional and preferable to relying on unsynchronized machine NBT for local mining prediction.

## Validation
The release validator checks that client attack handling passes through for Flint Plant Cutters, client destroy progress does not call server-only readiness checks, and the server-authoritative Lumber Processor validation remains present.

## Next release pressure
Continue Wood → Water progression after the Lumber Processor interaction loop is stable in normal playtesting.
