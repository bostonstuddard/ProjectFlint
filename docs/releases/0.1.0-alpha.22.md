# Project Flint 0.1.0-alpha.22 — Primitive Systems Consolidation

## Intent

Consolidate the primitive systems that had begun to drift apart before adding another progression tier. The release deliberately focuses on ownership boundaries, shared processing, tool inheritance, regression prevention, and a documented progression source of truth.

## Baseline

This release starts from the project-owner-uploaded alpha.21.7 source tree. The alpha.21.7.1 kiln/grinder dismantling hotfix was applied first, as explicitly requested, and that overlaid tree became the alpha.22 baseline.

## Player-facing behavior

- Clay Grinder opens through a Project Flint-owned container/screen rather than the vanilla Stonecutter implementation.
- The Grinder intentionally has no recipes yet and therefore produces no output.
- Campfire and Baked Kiln remain one-item-at-a-time timed processors.
- Unfinished Campfire/Kiln work remains stored while the fire is inactive and resumes after relighting.
- Super Heated Clay is kiln-only.
- Completed kiln output still ejects from the kiln's front face.
- Existing alpha.21.7.1 dismantling remains: Flint Multitool breaks the completed kiln pair for 2 Fired Clay and the Clay Grinder for 4 Super Heated Clay as world drops.
- Cutter-shaping a Crude Clay Block now gives the resulting Crude Clay Kiln the player's facing instead of defaulting north.

## Architecture

### Custom Clay Grinder

The Clay Grinder no longer inherits any vanilla Stonecutter container or recipe behavior. Alpha.22 introduces:

- `ModMenus.CLAY_GRINDER`;
- `ClayGrinderMenu extends AbstractContainerMenu`;
- `ClayGrinderScreen`;
- `ModRecipes.CLAY_GRINDING`;
- `ClayGrinderRecipe`;
- a Project Flint recipe serializer.

No `projectflint:clay_grinding` recipe JSON is shipped in alpha.22. The current GUI is code-rendered, so no assistant-authored GUI texture asset was added.

### Unified primitive processing

`AbstractPrimitiveProcessorBlockEntity` owns input, timer, persistence, and completion state for permanent heat processors. Campfire and Baked Kiln block entities provide only processor identity, active-state detection, and output-ejection geometry. `PrimitiveProcessingRegistry` is the shared recipe/station table.

### Tool capability boundary

`ToolCapabilities` is now the authoritative source for Hammer, Cutter, Multitool, Flint-tier, and finished-workstation-dismantle capabilities. Existing `ModItems` compatibility helpers delegate to it so older call sites can migrate without a behavior reset.

## Design reasoning

The previous Grinder repeatedly inherited unwanted Stonecutter behavior because it was structurally a Stonecutter menu with selective overrides. The replacement removes that dependency rather than suppressing more vanilla behavior. Similarly, Campfire and Kiln had duplicated processing state that had already produced instant/timed inconsistencies. A common processor state machine and explicit station applicability make those differences intentional instead of accidental.

Tool inheritance is centralized for the same reason: a Flint Multitool should inherit approved Hammer/Cutters capabilities because the capability table says so, not because every interaction handler remembered to add another item check.

## Tuning snapshot

No approved combat stats, durability values, material yields, existing stack limits, or current processing times were intentionally retuned. The important current values remain:

- Crude Hammer: 24 durability;
- Crude Cutters: 48 durability;
- Crude Multitool: 128 durability, 1.25× inherited primitive work speed;
- Flint Multitool: 256 durability, 2× inherited primitive work speed and the existing extra 2× foliage modifier;
- Super Heated Clay: 4-second kiln process;
- other current permanent heat recipes: 15 seconds each;
- Campfire burn: 30 seconds;
- completed Kiln burn: 5 minutes.

## Assets and licenses

The uploaded source archive also contained a sibling `ProjectFlint - Textures/` directory of redone 16x textures. Twenty-six matching active item/ground texture targets were replaced using exact byte-for-byte copies. No image generation, resize, redraw, recolor, compositing, filtering, or other pixel editing was used.

Those provenance rows use source archive `ProjectFlint sourceCode.zip` and exact paths/hashes in `docs/TEXTURE_PROVENANCE.md` and `docs/texture_provenance.json`. Supplied artwork for unimplemented concepts such as Ash, clay pots, a Woven Basket, and Wooden Toolbox was not silently turned into gameplay content.

## Advancement coverage

No advancement progression was intentionally removed or retuned in alpha.22. Existing milestones through the Clay Grinder remain in place. The consolidation primarily changes implementation boundaries rather than acquisition criteria. The developer progression matrix is now an additional regression gate alongside the advancement tree.

## Validation

The release validator checks:

- all JSON resources and existing progression/resource links;
- exact texture hashes/provenance, including the new user-redone source archive;
- absence of `StonecutterMenu` inheritance in the Grinder menu;
- independent Grinder menu/recipe registries and screen registration;
- zero actual Clay Grinder recipes in alpha.22;
- shared Campfire/Kiln processing architecture and kiln-only Super Heated Clay;
- centralized `ToolCapabilities` and Flint foliage speed routing;
- alpha.21.7.1 world-drop/salvage behavior;
- the crude-kiln facing regression fix;
- required sections in `docs/PRIMITIVE_PROGRESSION_MATRIX.md`.

A full Gradle build remains dependent on Fabric Loom plugin resolution in the build environment; the project-owner's local `build.bat` remains the authoritative full compile/run gate.

## Known limitations

- The custom Grinder recipe system exists but intentionally has no recipe JSONs yet.
- The code-rendered Grinder screen is functional development UI, not final human-authored art.
- Some older helper methods remain as compatibility facades while callers migrate to the new capability/processing boundaries.
- A local gameplay pass is still required for GUI interaction, shift-click behavior, and all progression regression gates after the full Fabric build succeeds.

## Next release pressure

- Design and approve the first actual `projectflint:clay_grinding` recipes rather than borrowing vanilla Stonecutter recipes.
- Decide whether grinder recipes need multiple selectable outputs for one input before alpha.23 populates the system.
- Continue moving direct tool/tier checks into the authoritative capability layer when a check represents capability rather than intentional yield tuning.
- Expand the processing registry only when Campfire/Kiln role differences are explicitly designed.
- Use the supplied but currently-unused human-made concept textures only when their corresponding gameplay systems are intentionally introduced.
