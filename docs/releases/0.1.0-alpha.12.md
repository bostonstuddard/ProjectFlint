# Project Flint 0.1.0-alpha.12 — Inventory Lock Alignment Fix

## Intent
Correct the visual regression where primitive inventory lock backgrounds rendered as a detached grid to the right/bottom of the inventory screen. This is a rendering-only repair based on the alpha.11 playtest screenshot.

## Player-facing behavior
- Locked inventory slots once again show their light-gray disabled treatment inside the actual locked slots.
- The detached 31-slot duplicate grid is removed.
- Items already inside slots and items being dragged by the cursor continue to render above the disabled-slot treatment.
- No inventory capacity, pickup, progression, stack-size, crafting, knapping, worldgen, animal, hunger, or interaction behavior changes.

## Architecture introduced
No new subsystem is introduced. `AbstractContainerScreenMixin` keeps its per-slot `renderSlot` injection, but now renders using `Slot.x` / `Slot.y` directly. Minecraft has already translated the GUI graphics pose to the container origin when this method renders slots, so adding `leftPos` / `topPos` a second time was incorrect.

## Design reasoning
The alpha.11 render-order fix was conceptually correct: lock art belongs underneath the item sprite. The regression came from mixing two coordinate spaces. Fixing only the coordinate calculation preserves the accepted render layering instead of moving the lock overlay back to a later screen pass and reintroducing the old item-under-lock problem.

No tuning values changed.

## Advancement coverage
No new technological capability or progression milestone is introduced, so no advancement is appropriate for this rendering-only release. Existing ProjectFlint advancement coverage is unchanged.

## Validation performed
- Verified `AbstractContainerScreenMixin` still injects at the head of `renderSlot`.
- Verified locked-slot detection still uses `PrimitiveInventorySystem.isLockedPlayerInventorySlot(slot)`.
- Verified the lock renderer uses slot-local coordinates and no longer adds `leftPos` or `topPos`.
- Verified no gameplay source files other than the rendering mixin were modified.
- Ran the Project Flint static release validator.

## Known limitations
The artifact environment cannot perform the final Fabric client render test. The local client remains the final validation gate for resource-pack-specific inventory positioning.
