# Project Flint v0.28.41-a — Crude Multitool leaf-harvest hotfix

## Intent
Restore the progression-critical foliage capability that was accidentally removed from the Crude Multitool.

## Player-facing behavior
The Crude Multitool can once again break vanilla leaves-tag blocks and produces **4 Twigs + 1 Branch** for 1 durability. This restores the first dependable Branch source after obtaining the Crude Multitool.

## Architecture
`ToolCapabilities.canHarvestLeaves(...)` once again includes `CRUDE_MULTITOOL`. Existing mining-progress, break-authority, and output paths already consume this shared capability, so one authoritative capability correction restores the complete interaction.

## Design reasoning
The Crude Multitool is intentionally the first tool that opens full leaf harvesting and Branch progression. Restricting foliage harvesting to Flint-tier tools creates a hard progression dead end.

## Tuning snapshot
- Crude Multitool leaves: **4 Twigs + 1 Branch**.
- Cost: **1 durability** per harvested leaf block.
- Higher-tier foliage outputs are unchanged.

## Assets and licenses
No assets were added, removed, or modified.

## Advancement coverage
The existing detailed Branch/Crude Multitool advancement guidance remains correct and required no content rewrite.

## Known limitations
No new limitations introduced.

## Validation
The release validator passes and explicitly checks that `CRUDE_MULTITOOL` remains in `canHarvestLeaves(...)` and that the existing Crude leaf-yield branch remains present. A full Gradle compile was attempted, but this environment still cannot resolve Fabric Loom `1.14.10` from its offline plugin cache.

## Next release pressure
Continue protecting progression-gating tool capabilities with explicit regression checks whenever plant/tool inheritance is refactored.
