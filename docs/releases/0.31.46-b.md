# Project Flint v0.31.46-b — Fish bucket component compile fix

## Purpose
Fix a Java compilation error introduced by the v0.31.45-b functional update on Minecraft 1.21.11 with Fabric Loom 1.14.10.

## Root cause
`DefaultItemComponentEvents.MODIFY` passes a `DataComponentMap.Builder`, whose 1.21.11 API defines `set(DataComponentType<T>, T)` but does not define `remove(DataComponentType<?>)`. Calling `builder.remove(DataComponents.FOOD)` in `FoodBalanceSystem` failed compilation with `cannot find symbol`.

## Fix
Changed the fish bucket loop's component mutation to `builder.set(DataComponents.FOOD, null)`. The 1.21.11 `DataComponentMap.Builder#setUnchecked` implementation removes a component from its map when the supplied value is null.

## Compatibility and behavior
- Minecraft 1.21.11 Fabric / Java 21 source compatibility; version bumped to **0.31.46-b**.
- Applies directly on top of **v0.31.45-b**; does not include the previous 56-file functional update.
- Fish buckets remain non-food items. The item tooltip code from v0.31.45-b independently excludes `MobBucketItem` from its food-stat lore.
- Hardwood crafting, mining checks, Fat-Burning Torches, kiln visuals and other prior gameplay mechanics are untouched.

## Validation
`javap` inspection of the locally available Minecraft 1.21.11 mapped JAR confirms `DataComponentMap.Builder#set` is present and `remove` is absent; bytecode confirms `set(..., null)` removes the key from the map. Full Gradle compilation and in-game behavior must be verified in the owner's full development environment.
