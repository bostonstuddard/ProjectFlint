# Project Flint 0.31.27-b — Well/Creative Lighting Hotfix

## Intent
Remove unnecessary Well air-cell strictness, repair the Well GUI progress overflow, and make Creative-mode bypasses behave like true bypasses rather than leaving primitive slowdown visuals or converting Creative lighting into fullbright.

## Player-facing behavior
- Decorative/non-structural cells around the Well upper frame no longer have to be empty air.
- The Well shaft center accepts water and replaceable clutter such as short grass; completed production can replace that clutter with source water.
- The Well progress bar advances normally instead of corrupting once the server work counter exceeds the container-data packet range.
- Creative/Spectator no longer show the slowed bare-hand vegetation swing on slow-clear blocks.
- Switching Creative <-> Survival updates Project Flint darkness immediately on the next lightmap render, without waiting on a world light change.
- Creative uses normal vanilla lighting. It bypasses only Project Flint's extra hardcore-darkness treatment; actual Night Vision still provides vanilla Night Vision brightening.

## Architecture
`WellMultiblock` now validates only required upper-frame cells. The lower shaft still requires its brick shell, while the center column permits air, water, or replaceable states so harmless world clutter does not invalidate an otherwise formed Well.

`WellPulleyBlockEntity` keeps its 120,000-unit server-side fixed-work cycle, but its `ContainerData` exposes a 0-10,000 display scale. This avoids Minecraft 1.21.11 `ClientboundContainerSetDataPacket` signed-short truncation while preserving high-resolution server timing.

`LightTextureMixin` uses a Project Flint-only negative `NightVisionFactor` sentinel for Creative players who do not actually have Night Vision. The custom lightmap shader interprets that sentinel as "use the vanilla lighting branch without Night Vision normalization." The mixin also detects Creative/Night-Vision bypass-state transitions at `updateLightTexture` entry and forces a lightmap refresh when the state changes.

## Design reasoning
Unused multiblock volume should not be structural. Requiring literal air made harmless vegetation or other non-structure states break Well formation for no gameplay benefit. The shaft remains protected from solid obstruction because only replaceable states/water are accepted there.

The Well progress corruption was a networking/UI issue, not a production-rate issue: container data is serialized as signed shorts, so a 120,000 maximum cannot be transmitted intact. Scaling only the display value keeps Rope/aquifer changes as rate modifiers and leaves current work monotonic.

Creative should bypass Project Flint restrictions but should not gain a different vanilla visual baseline. Separating Creative's darkness bypass from actual Night Vision preserves vanilla Creative lighting.

## Tuning snapshot
- Base Well cycle remains 60 seconds at 100 effective quality.
- Server Well work target remains 120,000 fixed work units.
- GUI Well progress scale is 0-10,000.
- Each Rope still adds +2 quality points, up to +32 from 16 Rope.
- Aquifer qualities remain Scarce 25%, Normal 60%, Good 85%, Abundant 120%.

## Assets and licenses
No new art assets are introduced. The only resource change is the existing Project Flint lightmap shader logic.

## Advancement coverage
None. Advancements remain retired in favor of Flint Quests.

## Known limitations
- Well Pulley final art is still pending.
- A non-replaceable solid block in the three-block shaft center still prevents Well formation because it would physically block the generated water column.
- Brick recovery gating remains global for vanilla Bricks, matching the prior release.

## Validation
The release validator checks relaxed non-structural Well validation, replaceable shaft handling, GUI-safe scaled Well progress, Creative slow-swing bypass, Creative lighting sentinel behavior, and forced lightmap refresh on bypass-state transitions.

The sandbox's bundled Gradle state does not include the Loom plugin artifact required for an offline Gradle build, so a normal connected Java 21 `build.bat` run remains the final full compile/runtime gate.

## Next release pressure
Playtest Well formation with vegetation/water in the interior, verify progress across all aquifer qualities and Rope stack changes, and test repeated Creative <-> Survival transitions at night without changing nearby block light.
