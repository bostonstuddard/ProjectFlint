# Project Flint 0.1.0-alpha.7 — Progression Safeguards

## Intent
Apply only the two requested progression safeguards from the alpha.6 playtest: prevent creeper explosions from yielding mineable block loot, and make Creative-created test worlds use Hardcore semantics whenever the player switches into Survival without reintroducing the old runtime gamemode restrictions.

## Player-facing behavior
- Creeper explosions still destroy blocks and still damage entities normally, but blocks destroyed by the creeper explosion produce no item drops.
- This prevents a player from luring a creeper out of a cave to obtain otherwise progression-locked terrain resources.
- Project Flint worlds report Hardcore semantics to the running server even when the world was originally created in Creative.
- A Creative test world can still freely switch to Creative, Survival, or Spectator when commands permit it; Project Flint does not intercept those gamemode changes.
- If that Creative-created world is switched to Survival, the client/server treat the world as Hardcore for Hardcore UI/death behavior.
- The existing world-creation default remains Hardcore, with Creative retained as the development option.

## Architecture introduced
Two focused common mixins are introduced:

- `ServerExplosionMixin` intercepts only the block-drop aggregation step of `ServerExplosion`. When the direct explosion source is a Creeper, generated block stacks are discarded before item entities are created. Terrain destruction itself is not cancelled.
- The existing `PrimaryLevelDataMixin` is re-enabled and makes the world data's `isHardcore()` query return true. Vanilla server/client Hardcore checks can therefore follow their normal path without blocking or rewriting runtime game mode changes.

## Design reasoning
Creepers should remain an environmental threat capable of damaging terrain, but the resulting destruction must not function as an alternate mining technology. Suppressing only the generated explosion loot closes that progression bypass while preserving the consequence of the blast.

The earlier alpha.4 approach incorrectly tried to enforce Hardcore by controlling runtime gamemodes, which broke Spectator. Alpha.5 correctly removed that restriction. The alpha.7 requirement is narrower: all Project Flint worlds should *carry Hardcore semantics* even when created in Creative for testing. Answering the world data's normal Hardcore query with `true` preserves vanilla Creative/Spectator switching while ensuring that entering Survival does not become ordinary respawnable Survival.

## Tuning snapshot
- Creeper block destruction: unchanged.
- Creeper explosion block drops: 0%.
- Other explosion sources: unchanged.
- World-data Hardcore semantic flag: always true.
- World-creation choices, Hard difficulty enforcement, mob tuning, inventory limits, grass/bush timings, and primitive stack limits are unchanged from alpha.6.

## Assets and licensing
No assets changed and no third-party material was added.

## Validation performed
- Parsed all JSON resources with the Project Flint release validator.
- Verified `ServerExplosionMixin` checks the direct explosion source specifically for `Creeper` and suppresses only `ServerExplosion.addOrAppendStack` for that source.
- Verified non-creeper explosion drops still call the original `addOrAppendStack` path.
- Verified `PrimaryLevelDataMixin` changes only `PrimaryLevelData.isHardcore()` and does not intercept `setGameMode`, Spectator, respawn commands, or player gamemode packets.
- Verified `ServerPlayerMixin`, the old runtime gamemode restriction, remains inactive.
- Verified all alpha.6 primitive inventory/stack behavior remains unchanged.

## Known limitations
The artifact environment still cannot launch Minecraft, so the local Fabric build/client launch remains the final mixin-application and Hardcore death-screen validation gate. Creeper explosions involving unusual modded blocks with custom explosion-drop behavior should be retested later if such blocks are added.
