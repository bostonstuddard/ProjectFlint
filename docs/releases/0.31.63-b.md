# Project Flint v0.31.63-b — Custom Block Breaking / Flint Quests Compatibility

## Intent
Fix Stone-breaking quests not progressing in the bundled Project Flint + Flint Quests experience.

## Player-facing behavior
Hammering natural Stone into Crushed Stone counts as breaking Stone for Flint Quests. Other successful Project Flint manually handled block breaks report the original block in the same way. No new crafting or item changes.

## Architecture
The server `ServerPlayerGameModeMixin` snapshots the original state/block entity and mining entitlement, then, on a canceled manual operation that actually changed the target block, dispatches Fabric `PlayerBlockBreakEvents.AFTER` exactly once. Its listeners include Flint Quests' existing generic BREAK_BLOCK tracker. Vanilla successful breaks are left to Fabric; invalid restricted mining attempts do not send an event.

## Design reasoning
Preserve generic event interoperability with other mods, without depending on Flint Quests or creating custom quest-event IDs. Do not count byproducts or neighboring transformations as breaks.

## Tuning snapshot
Crude Hammer Stone processing: 234 ticks, 4 Rocks, 1 tool durability, Stone -> Crushed Stone. Unchanged. No ore/tool speed changes.

## Assets/licenses
None.

## Advancement and quest coverage
Existing Project Flint advancement awarding remains unchanged; now Flint Quests BREAK_BLOCK minecraft:stone can progress when a player completes the Stone conversion. No new player quest IDs or quests are added.

## Known limitations
A live game run with the actual 0.32.0 combined bundle is required to verify end-to-end task completion. This Project Flint source update must be rebuilt and the new JAR substituted into the bundle before it can take effect.

## Validation
Static regression checks, Java API signature verification with 1.21.11 remapped Fabric API, JSON parsing, and ZIP integrity (see packaging report). No runtime JAR build or in-game test claimed.

## Next release pressure
