# Project Flint v0.31.1-b

## Intent

Restore the intended Flint Plant Cutter Sugar Cane behavior without changing any other plant-tool progression. The hotfix specifically removes the regression where an entire cane column could be deleted while only one roll was returned.

## Player-facing behavior

- Breaking Sugar Cane with Flint Plant Cutters now harvests the targeted cane block and every connected Sugar Cane block above it.
- The top block alone produces 1 Sugarcane Roll.
- Breaking a middle block produces one Sugarcane Roll for that block plus one for each cane block above it.
- Breaking the bottom block harvests the full column, matching vanilla cascading Sugar Cane break behavior.
- Output is exactly 1 `projectflint:sugarcane_roll` per harvested Sugar Cane block.
- The complete column harvest costs 1 Flint Plant Cutter durability total.
- Advanced Flint Multitools and the other Plant Cutter-like paths keep their existing normal-Sugar-Cane output behavior.

## Architecture

`ServerPlayerGameModeMixin.destroyBlock` previously contained two dedicated Flint Plant Cutter Sugar Cane branches. The earlier stale branch removed the Sugar Cane column and then hard-dropped a single `projectflint:reed_roll`, returning before the later column-aware implementation could run.

v0.31.1-b deletes that stale branch. The surviving handler calls `projectflint$removeSugarCaneColumn(pos)`, receives the exact number of cane blocks removed from the targeted block upward, and creates `new ItemStack(ModItems.SUGARCANE_ROLL, harvested)` from that count.

The existing helper intentionally begins at the block the player broke and walks upward only, so cane below a middle/top break remains in place just as expected.

## Design reasoning

Flint Plant Cutters are the dedicated Sugarcane Roll tool. Their special processing should replace each vanilla Sugar Cane item that would have dropped from the broken portion of the column, not collapse an arbitrary-height harvest into one item. Counting the removed blocks also keeps the result deterministic and directly tied to vanilla-style column behavior.

The action remains a single tool use, so durability is charged once for the harvest rather than once per cane block.

## Tuning snapshot

- Sugarcane Roll yield: **1 per harvested Sugar Cane block**.
- Harvest scope: **targeted block + every connected Sugar Cane block above it**.
- Flint Plant Cutter durability cost: **1 per completed break action**.
- No changes to Sugar Cane growth, world generation, stack size, or grinder recipes.

## Assets and licenses

No textures, models, sounds, or other external assets are added or modified by this hotfix.

## Advancement coverage

The existing `sugarcane_roll` advancement remains authoritative and is still awarded from the surviving Flint Plant Cutter handler. No new advancement is required because this release corrects the behavior of an already-documented progression step.

## Known limitations

This hotfix intentionally does not redesign generic Sugar Cane harvesting for other tools. It only restores the dedicated Flint Plant Cutter path and leaves the Advanced Flint Multitool/other Plant Cutter-like behavior unchanged.

## Validation

Release validation now requires exactly one dedicated Flint Plant Cutter Sugar Cane handler in `ServerPlayerGameModeMixin`, verifies that the harvested column count is used for `SUGARCANE_ROLL` output, and rejects the stale single-`REED_ROLL` branch if it reappears.

The v0.31.0-b Sanding Station missing-`Block` import compile fix is carried forward in this patch so v0.31.1-b remains self-contained.

## Next release pressure

Continue regression testing plant-tool specialization whenever shared harvesting logic is refactored, especially where a dedicated tool path and a generic `isPlantCutterLike` path coexist in the same block-break hook.
