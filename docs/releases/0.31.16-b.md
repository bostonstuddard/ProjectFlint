# Project Flint v0.31.16-b

## Intent
Fix Mod Menu compatibility in the No-Realms title-screen integration without restoring the Realms service or its background availability polling.

## Player-facing behavior
- The Minecraft Realms button remains removed.
- Mod Menu's **Mods** button is preserved again.
- With Mod Menu's normal/classic layout, the Mods button moves into the removed Realms row and the lower title-screen controls follow it upward.
- Mod Menu replacement/compact layouts are left in place instead of being shifted into overlapping controls.
- Realms notification/news/trial/invite UI remains disabled.

## Architecture
`TitleScreenMixin` now leaves the vanilla widget tree untouched during `TitleScreen.init()`. It removes/reflows the Realms row at the first render instead, after title-screen compatibility callbacks have finished adding their widgets. `MinecraftRealmsMixin` is no longer active because hard-returning `false` from `Minecraft#allowsRealms()` changed the vanilla title-screen state too early for Mod Menu compatibility. `RealmsAvailabilityMixin` remains active to resolve Realms availability locally without the service request.

## Design reasoning
Compatibility mods should see the normal vanilla title-screen structure while they initialize. Project Flint can still remove Realms before the first visible frame, but it should do so only after those integrations have finished.

## Tuning snapshot
The normal empty Realms row still closes by Minecraft's existing 24-pixel vertical button spacing. If another widget already occupies the removed row, no second vertical shift is applied.

## Assets and licenses
No external code or assets were imported. The fix was implemented against Project Flint's Minecraft 1.21.11 title-screen classes and checked against Mod Menu's public title-screen integration behavior.

## Advancement coverage
No advancement changes.

## Known limitations
Extremely unusual title-screen mods that add unlabeled full-width controls at the exact Realms row may need their own compatibility rule later.

## Validation
The release validator checks that Realms availability short-circuiting remains active, the early `allowsRealms()` hard-disable is no longer active, and title-screen removal is deferred to `render` rather than occurring during `init`.

## Next release pressure
Continue watching title-screen compatibility as additional client UI mods are introduced.
