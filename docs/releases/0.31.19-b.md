# Project Flint 0.31.19-b — PF-EMI Standalone Development Bridge

## Intent
Allow PF-EMI development to happen independently from Project Flint and promote only approved PF-EMI JARs into the main mod.

## Player-facing behavior
No gameplay changes. PF-EMI remains bundled inside the Project Flint JAR and does not need to be installed separately by players.

## Architecture
Project Flint continues to resolve `libs/PF-EMI-1.21.11.jar` through the local `flatDir` module and Loom `include`. The internal PF-EMI version is no longer pinned in Project Flint's Fabric metadata.

## Design reasoning
The JAR filename is the stable integration boundary. PF-EMI may be edited and versioned in its own source tree, then copied into Project Flint only when that build is approved.

## Tuning snapshot
- Stable nested filename: `PF-EMI-1.21.11.jar`
- Required nested mod id: `emi`
- Required nested display name: `PF-EMI`
- Required Minecraft target: `1.21.11`
- Current approved internal version: `1.1.23-pf.1+1.21.11+fabric`

## Assets and licenses
No Project Flint assets changed. PF-EMI remains based on EMI under the MIT license and is bundled as its own JAR.

## Advancement coverage
No advancement changes.

## Known limitations
Promoting a new PF-EMI build requires replacing the stable JAR and regenerating `libs/PF-EMI-1.21.11.sha256` before Project Flint validation/build.

## Validation
The release validator verifies the promoted JAR hash against its sidecar and inspects `fabric.mod.json` to require `emi`, `PF-EMI`, and Minecraft 1.21.11.

## Next release pressure
Future PF-EMI work can now be done in a separate source/chat workflow without a Project Flint version bump for every experiment; only approved promotions need to touch the nested payload.
