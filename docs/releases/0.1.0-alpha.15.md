# Project Flint 0.1.0-alpha.15 — Interaction Consistency and Stability Pass

## Intent

Apply the first large post-alpha.14 playtest batch without retuning unrelated systems. This release removes the frustrating Loose Rock placement behavior, closes floating ground-placement exploits, makes primitive tool actions use the same readable break-progress presentation, fixes cutters consistency, stabilizes dropped-item pickup and creeper explosions, repairs tall-flower harvesting, makes Rock-on-Crushed-Stone refinement reliable, and turns the advancement page into a more useful guide instead of a vague linear strip.

## Player-facing behavior

### Loose Rocks and ground placement

- The survival **Loose Rock item is no longer placeable**. Naturally generated Loose Rock blocks remain in the world and are still the opening source of Rocks.
- The old Rock Stockpile block ID remains registered for old test-world compatibility, but a normal Rock no longer starts a new Rock Stockpile.
- Primitive ground objects now require a sturdy supporting block beneath the placement position. This applies to Loose Rock world blocks when directly placed, Twig Piles, Fiber Work Piles, hammer/binding/cutters assemblies, legacy Rock Stockpiles, and Very Refined Stone stockpiles.
- The redundant Loose Rock block item is removed from the Project Flint creative tab so the ordinary progression Rock is not confused with a placeable worldgen block item.

### Primitive break-progress consistency

The same center-screen progress meter used by early hand operations now appears while actively performing supported tool operations:

- Crude Stone Hammer on Stone;
- Crude Stone Hammer on Sugar Cane;
- Crude Stone Cutters on Short Grass;
- Crude Stone Cutters on Leaf Litter;
- Crude Stone Cutters on flowers.

The actual operation times are unchanged from alpha.14 unless listed elsewhere in this release.

### Crude Stone Cutters

- Leaf Litter can now be processed with the cutters instead of being an unexplained exception to the foliage-clearing rules.
- Each Leaf Litter block yields **2 Plant Fiber**, produces no vanilla Leaf Litter drop, and costs **1 cutter durability**.
- Short Grass still yields 1 Crude Plant String for 1 durability.
- Flowers still yield 1 Flower Petals for 1 durability.
- Two-block-tall flowers are removed as a complete plant before the custom reward is granted, preventing the paired vanilla flower item from dropping alongside Flower Petals.

### Dropped items and pickup

- World-item pickup through the five primitive inventory slots now supports **partial pickup**.
- If only part of a dropped stack fits, the fitting amount is inserted and the remainder stays in the same world item entity.
- This replaces alpha.14's all-or-nothing pickup rule, which could make dropped stacks appear stuck or inconsistent when only partial capacity was available.

### Creeper explosions

- Creepers still damage entities and destroy terrain.
- Creeper-destroyed blocks still produce **no block-item loot**, preserving the progression safeguard from alpha.7.
- The implementation no longer redirects through `ServerExplosion`'s private internal `StackCollector` helper. Instead, creeper explosions use the normal block explosion path with a no-op drop collector, eliminating the crash-prone interception point.
- Non-creeper explosion drop handling remains unchanged.

### Rock refinement

- Right-clicking persistent Crushed Stone with a Loose Rock now performs the conversion explicitly on the server: one Rock is consumed and one Very Refined Stone is delivered through the primitive inventory/drop path.
- The Crushed Stone surface remains in place.
- This replaces reliance on the item-use held-stack transformation result, which was unreliable in the current custom inventory/interact flow.

### Advancement page

- Existing advancement descriptions have been rewritten to state concrete requirements, quantities, tool costs, chances, and outputs instead of vague summaries.
- The tree has been re-parented into meaningful branches for gathering/material processing, hammer stonework, and cutters harvesting, giving the page substantially more vertical structure.
- The former Rock-stockpile milestone is now **Stone Reserve**, awarded for starting a Very Refined Stone stockpile, since ordinary Rock placement has been removed.
- Added **Rake the Forest Floor** for harvesting Leaf Litter into Plant Fiber with the cutters.

## Architecture

- `RockItem` is now a normal `Item`, not a `BlockItem`. It owns only stone working and Crushed Stone refinement.
- Ground-support validation is centralized in `BlockStateBaseMixin#canSurvive` for Project Flint's primitive ground assemblies/piles instead of duplicating placement checks across every BlockItem implementation.
- `PrimitiveHud` now presents destroy-stage meters for the hammer and cutters operations already governed by `BlockStateBaseMixin` destroy-progress rules.
- `ItemEntityMixin` mutates a copy through `PrimitiveInventorySystem`, inserts the fitting portion, and updates/discards the world entity according to the remainder.
- `ServerExplosionMixin` redirects `BlockState#onExplosionHit` rather than the private `ServerExplosion#addOrAppendStack` helper.
- `ServerPlayerGameModeMixin` handles cutters Leaf Litter conversion and explicitly removes paired `DoublePlantBlock` halves for no-drop tall-flower harvesting.

No generalized tool-operation registry is introduced in this patch; these fixes remain within the current primitive-operation architecture.

## Design reasoning

Removing ordinary Rock placement is preferable to trying to polish a mechanic that already proved annoying in direct playtesting. Very Refined Stone remains the intentional early stockpile material, so primitive physical storage still exists without making the most common opening resource awkward to use.

Ground objects are physical assemblies and should read as objects resting on terrain. Central support validation guarantees that rule across the current assembly family and prevents new BlockItem paths from quietly reintroducing floating placement.

The progress meter is part of Project Flint's interaction language. If two actions both require a long hold-to-break, hiding the meter for one of them makes the system feel arbitrary even when the server-side timing is correct.

Partial pickup preserves the five-slot limit while matching normal player expectations: available space should accept what it can, not reject an entire world stack.

The creeper progression rule is kept, but the implementation is moved to a public block-explosion callback boundary rather than depending on a private nested collector implementation.

## Tuning snapshot

Unchanged values retained from alpha.14:

- Crude Stone Hammer durability: 24.
- Crude Stone Hammer total attack damage: 2.0.
- Crude Stone Hammer attack speed: 0.8.
- Crude Stone Cutters durability: 48.
- Crude Stone Cutters total attack damage: 1.0.
- Crude Stone Cutters attack speed: 1.2.
- Short Grass cutters output: 1 Crude Plant String; 1 cutter durability.
- Flower cutters output: 1 Flower Petals; 1 cutter durability.
- Very Refined Stone stack/stockpile capacity: 8.

New/changed behavior:

- Leaf Litter cutters output: **2 Plant Fiber**; 1 cutter durability.
- Ordinary Loose Rock placement: disabled.
- World-item pickup: partial insertion allowed within the same five legal primitive slots.

No grass scrape chance/speed, stone hammer speed, bush yield, fire chance, knapping chance, animal, hunger, worldgen, or carrying-capacity tuning is changed.

## Assets and licenses

No new texture/model/audio asset was imported for alpha.15. The two user-provided Project Flint-approved resource packs remain available for future asset work, but this bug-fix batch did not copy material from them.

`docs/ASSET_SOURCES.md` and `docs/TEMPORARY_ASSETS.md` therefore require no content change for this release.

## Advancement coverage

Reviewed and expanded as a release gate:

- All current primitive advancement descriptions now explain the concrete action rather than only naming the concept.
- Branching was increased around Stone/Fiber development, hammer operations, and cutters outputs so the advancement view has meaningful vertical spread.
- `stone_stockpile` keeps its persistent internal ID but is now the **Stone Reserve** Very Refined Stone stockpile milestone.
- Added `leaf_litter_fiber` / **Rake the Forest Floor** for the new cutters capability.
- Tall-flower drop suppression, partial pickup, progress-meter presentation, creeper crash repair, and refinement transaction hardening are fixes to existing capabilities and do not need separate advancement nodes.

## Known limitations

- The old `projectflint:rock_pile` block and models remain registered for compatibility with existing test worlds even though ordinary Rocks can no longer start new piles.
- The internal cutters ID remains `projectflint:crude_harvesting_tool` for compatibility.
- Tool operations are still hard-coded targeted interactions rather than a data-driven CUT/SCRAPE/CRUSH operation registry.
- Ground-support validation prevents unsupported placement; alpha.15 does not add a new component-recovery system for the separate case where terrain beneath an already placed assembly is later removed.
- Full Fabric runtime launch validation still has to be performed in an environment where Fabric Loom 1.14.10 resolves successfully.

## Validation

- Parsed all Project Flint JSON resources after the advancement rewrite.
- Reviewed advancement parent links for a connected, acyclic tree rooted at `projectflint:root`.
- Checked the new Leaf Litter cutters route against the same slow-break target tag used by bare-hand clearing.
- Checked the tall-flower removal path against Minecraft 1.21.11 `DoublePlantBlock.HALF` / `DoubleBlockHalf` mappings.
- Checked the creeper redirect target against Minecraft 1.21.11 `ServerExplosion#interactWithBlocks` bytecode and `BlockState#onExplosionHit` signature.
- Attempted Gradle `compileJava` offline; Fabric Loom 1.14.10 is not present in the available plugin cache, so Gradle cannot configure the project in this artifact environment.
- Compiled the complete Java source tree with Java 21 against the cached Minecraft 1.21.11 and remapped Fabric API classes, using temporary compile-only stubs only for external classes missing from the broken Loom environment. The source compile completed with no Java errors.
- Static source/resource validation and the full Java source compile check are the available artifact-environment validation path; a local `build.bat` build and live client test remain release gates.

## Next release pressure

Continue broadening the tool-operation vocabulary and early material loop only from new playtest notes. In particular, future work can formalize cutter/hammer target data, replace temporary art from the approved asset sources where appropriate, and continue making advancements function as an actual in-game progression guide without reintroducing removed Rock placement.
