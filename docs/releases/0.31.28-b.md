# Project Flint 0.31.28-b — PF-EMI Ownership Cleanup

## Intent
Remove Project Flint's obsolete EMI recipe/index plugin and compile-time PF-EMI bridge so PF-EMI is the sole owner of Project Flint recipe discovery, recipe pages, item filtering, and multiblock presentation.

## Player-facing behavior
- No Project Flint gameplay recipe or processing behavior changes in this release.
- PF-EMI can now present the complete Project Flint catalog without Project Flint deleting EMI's normal recipe catalog or re-registering a partial subset.
- Physical/in-world crafting, Well processes, Lumber Processor processes, machine recipes, knapping, stone working, and other gameplay systems remain owned and executed by Project Flint.
- Players still install Project Flint and PF-EMI as separate runtime JARs.

## Architecture
`ProjectFlintEmiPlugin` is deleted completely. Project Flint no longer imports `dev.emi.emi.*`, declares an `emi` entrypoint, or compiles against a local PF-EMI JAR.

`fabric.mod.json` retains `"emi": "*"` in `depends` because PF-EMI intentionally keeps the Fabric mod ID `emi`. The only Project Flint entrypoints are now `main` and `client`.

`build.gradle` no longer uses `flatDir` for PF-EMI and no longer declares `modCompileOnly` or any other PF-EMI compile/runtime/include dependency. `libs/PF-EMI-1.21.11.jar` and its obsolete SHA sidecar are removed from Project Flint source. `build.bat` no longer requires either file, while its final output-JAR nested-PF-EMI safety check remains active.

Project Flint remains the gameplay source of truth. PF-EMI is now exclusively the presentation/discovery layer.

## Design reasoning
Two independent EMI owners cannot safely coexist. The deleted Project Flint plugin intentionally removed non-Project-Flint recipes and then reconstructed only the subset it knew about, which meant newer or externally represented systems could disappear from EMI even though their gameplay logic still existed.

The clean boundary is therefore one-way: Project Flint exposes real mechanics through its normal gameplay code, while PF-EMI reads/represents those mechanics externally. Project Flint must not filter, delete, duplicate, or re-register EMI recipes.

## Tuning snapshot
No tuning values changed. Well timing/quality/output, Lumber Processor timing/structure, kiln and oven processing, grinder/sanding/bookshelf recipes, physical assemblies, knapping, inventory rules, darkness, and progression behavior are unchanged from v0.31.27-b.

## Assets and licenses
No visual assets were added or modified. The six Project Flint-owned EMI category translation keys used only by the deleted plugin were removed; normal Project Flint item/block/menu translations remain intact.

## Advancement coverage
None. Advancements remain retired in favor of Flint Quests, and Flint Quests integration is unchanged.

## Known limitations
- PF-EMI must be installed separately at runtime because Project Flint still requires an external mod providing Fabric mod ID `emi`.
- Recipe/index completeness is now entirely the responsibility of PF-EMI; Project Flint intentionally contains no replacement EMI plugin.

## Validation
The release validator now requires the Project Flint EMI plugin to be absent, rejects all `dev.emi.emi` Java imports, rejects the old PF-EMI Gradle compile bridge/local JAR, requires no `emi` entrypoint while retaining the `"emi": "*"` runtime dependency, checks removal of the obsolete EMI category translations, and preserves the built-JAR nested-PF-EMI guard.

The patch was also diff-checked to ensure no gameplay Java source changed besides deletion of the obsolete EMI plugin.

## Next release pressure
Continue PF-EMI work externally: represent the complete physical/in-world crafting catalog, Well outputs/processes, Lumber Processor recipes, heat stations, and GregTech-style multiblock views without adding EMI ownership back into Project Flint.
