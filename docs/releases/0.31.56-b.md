# Project Flint v0.31.56-b — Physical Basin Processing & Crafting Durability

## Intent
Give the Basin a physical item representation and difficulty-based stomp processing, and correct the serious Hardwood Crafting Table bug that deleted durable tools instead of wearing them.

## Player-facing behavior
An item visibly rests in the Basin when inserted; stomping progresses toward a recipe-specific threshold. Planks need 2 stomps, stripped Oak/Birch 3, Raw Iron 5, Raw Copper 4, stone family 4, Slag 3, Gravel and Stone Dust 2, Sand 2. A completed input costs 1 hunger point; intermediate landings cost none. A canceled/removed input loses its progress. All previous probabilistic outputs are unchanged. In the Hardwood Table, Bone Knives and Flint Files return with 1 durability consumed per use rather than disappearing, while the 3-second timer still applies per craft.

## Architecture
Server `BasinBlockEntity` stores both the item and stomp counter, synchronizes them via BE packets, and delegates independent byproduct rolls to `BasinMaterialProcessingSystem`. The client `BasinItemRenderer` presents the true `ItemStack` with the Minecraft 1.21.11 render-state API; blockstate variants render only the basin body. Hardwood result slot calculates remainders from the matched dedicated `HARDWOOD_CRAFTING` recipe, avoiding vanilla `ResultSlot`'s hardwired `RecipeType.CRAFTING` lookup. Recipe refresh is suppressed while consuming the craft grid transaction.

## Design reasoning
Difficult materials take more exertion without multiplying the already-established hunger penalty; actual item rendering avoids misleading generic wood placeholders and preserves all approved player-supplied textures. Durable crafting tools remain progression investments rather than one-use ingredients.

## Tuning snapshot
1 hunger point per completed Basin input; 2–5 stomps depending on input; 60 ticks per Hardwood craft; 1 durability per knife/file use; same v0.31.55-b output probabilities.

## Assets and licenses
No new external textures or fonts. Basin renders existing item models and textures from vanilla/Project Flint. No AI-generated art.

## Progression and quest coverage
No new items or progression milestones were added. Existing Flint Quests milestones remain authoritative. Guides updated for interaction rules; no duplicate Minecraft advancement tree.

## Validation
Mapped Minecraft 1.21.11 class paths used for API inspection, source/JSON/ZIP checks. Full Gradle compile not available in this environment because Fabric Loom 1.14.10 is not cached offline. Live singleplayer/multiplayer validation pending.

## Known limitations
One item model is displayed for a stacked Basin input; other items remain in the same block entity. Visual styling at different Minecraft GUI scales and live click interactions still need an in-game check.

## Regression checklist
- All accepted Basin inputs show their real item textures, not hard-coded wooden insets; empty Basin shows no item.
- Stomp counts exactly match table, persisted through chunk reload; single hunger cost only on completion.
- Removing an input resets progress and returns exact item; byproducts keep independent rolls.
- No instant output from the Hardwood Crafting Table; each shift-click must still wait 60 server ticks.
- Bone Knife + Flint File durable recipes return each tool with 1 damage; final use breaks at zero; full inventory neither deletes nor duplicates remainders.
- Ordinary materials are still consumed and ingredient containers/molds returned.

## Next release pressure
Validate the new 1.21.11 renderer and remainder handler in a live client, especially stacked inputs and shift-clicks; balance stomp counts through playtesting if needed.
