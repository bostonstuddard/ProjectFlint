# Project Flint v0.31.37-b — Fireclay Forge fuel and tooltip correction

## Intent
Fix the Fireclay Forge's unexpectedly profitable one-log fuel usage and keep internal development descriptions out of player-facing tooltips.

## Player-facing behavior
- A Forge ignition with logs/wood requires and immediately consumes **4** valid logs/wood. It supplies **60 seconds** of heat and produces exactly **4 Charcoal**, one every 15 seconds, for a **1:1 wood-to-charcoal return**.
- One Charcoal still supplies 5 minutes of heat and produces no additional Charcoal. Each ignition, including automatic ones, spends one Firestarter durability.
- A partial stack of 1–3 logs/wood will not ignite. Existing output-capacity and multiblock validity protections remain in force.
- Forge input, fuel, Firestarter, main output and Charcoal-output hover descriptions are concise and player-oriented. Fuel and Firestarter details use separate tooltip lines, not a single oversized line. Brick Furnace fuel help is also two lines.

## Architecture
The Forge's existing inventory-slot layout, save keys, server-authoritative processing timer, automatic relight, independently reserved primary output, and PF-EMI external ownership remain unchanged. `ignite()` checks wood stack size before charging the starter or shrinking fuel. Client tooltips use Minecraft's list-of-Components tooltip API and localization keys.

## Design reasoning
Four logs burned for 60 seconds yield four Charcoal at 15-second intervals, rather than duplicating three additional Charcoal from one log. Fuel guidance stays distinct from actual forge processing recipes.

## Tuning snapshot
| Fuel cost | Heat duration | Charcoal return |
|---|---:|---:|
| 4 valid logs/wood | 60 seconds | 4 (one every 15 seconds) |
| 1 Charcoal | 5 minutes | 0 |

## Assets and licenses
No textures, models, fonts or externally sourced assets were added or modified.

## Advancement coverage
ProjectFlint advancements remain retired; Flint Quests and existing recipe-guide integrations are unchanged.

## Known limitations
The Forge's main recipe slot is reserved for future actual processing recipes; none were invented in this fix. A running saved fuel cycle initiated in an older release can complete with its previously recorded burn state. Full Gradle/Loom compilation still requires an available Fabric Loom 1.14.10 artifact.

## Validation
Run `python tools/validate_release.py`, then the normal Windows `build.bat` and check four-log and single-Charcoal ignition, output blocking, save/reload, automatic continuation, GUI tooltips at low screen resolutions and on both client/server.

## Next release pressure
In-game confirmation of all tooltip render paths and Forge save migration, and incorporation of any independently reported screenshot issue once its attachment is available.

## Compile hotfix (patch 02)
The six reported compiler errors arising from three source-level issues were addressed without changing gameplay: vanilla crafting suppression and personal-recipe discovery now call `ResourceKey.identifier()` rather than the removed `location()` method; Tanned Leather armor registration imports `net.minecraft.world.item.Items`. The release validator checks all three regression points. This is a source-only hotfix for v0.31.37-b.
