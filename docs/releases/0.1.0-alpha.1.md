# 0.1.0-alpha.1 — Foundation

Date: 2026-08-08

## Intent

Create the first coherent vertical slice of Project Flint: the player should spawn with almost no ability to reshape the world, yet have a visible route from bare hands to the first worked material and first harvested woody resource.

This release also establishes the project structure and documentation discipline needed for a long-lived total overhaul.

## Player-facing behavior

### Terrain authority

Normal survival block destruction is denied by default. Creative mode bypasses this rule. A small `breakable_by_hand` tag exists for intentionally trivial placed utility blocks.

### Grass scraping

An empty-handed player can repeatedly attack a grass block. Five registered scrapes convert it to dirt. There is a small chance to recover one Plant Fiber.

The point is not that a human can literally excavate a cubic meter of earth after five motions. The mechanic establishes the design distinction between **altering a surface** and **collecting a terrain block**.

### Loose rocks

Small Loose Rock blocks generate on overworld surfaces. Empty-hand interaction gathers a Loose Rock item rather than mining the block into itself.

### Stone working

With a Loose Rock in each hand, using the main-hand rock performs one abstract stone-working strike. Six in-game strikes complete one attempt. The attempt has a 40% chance to produce a Refined Rock.

On success, the main-hand source stone is consumed and the off-hand source stone remains. Failed attempts consume no stone in alpha 1.

### Forage bushes

Forty separate forage-bush IDs cover the terrestrial surface biomes supported in this alpha. Each biome gets its own registered block and placed feature rather than sharing one generic bush ID. Aquatic and underground biomes are intentionally excluded because they need different early-forage resources instead of implausible surface twig bushes.

The blocks share one mechanic in Alpha 1: they cannot be normally punched apart, and a Refined Rock harvests the bush for 1–3 Twigs. Their separate IDs are infrastructure for later biome-specific appearance, yield, regrowth, seasonal behavior, and ecology.

### Animals retaliate

When a player damages a vanilla `Animal`, that animal temporarily pursues the attacker and deals a small contact attack. This prevents the opening food strategy from being completely risk-free without pretending every species has identical final behavior.

## Architecture introduced

- registry classes for items, blocks, and tags
- centralized gameplay tuning constants
- primitive contextual interaction event pipeline
- separate stone-working session system
- separate animal retaliation system
- data-driven configured/placed worldgen features
- biome feature attachment module
- release, architecture, design, roadmapping, and asset-license documentation

No mixins are used.

## Design reasoning

### Why breaking is deny-by-default

A blacklist would immediately become fragile: every new vanilla/modded block would be punchable until explicitly forbidden. The overhaul's premise is the opposite. Players start without an operation and acquire operations later, so permission should be additive.

### Why stone working is short-cycle random

The requested fantasy includes repeated stone-on-stone work and uncertainty. Six-strike cycles preserve that feeling. A failed cycle does not destroy material because the project has not yet added enough surrounding resource gameplay for loss to create an interesting decision; at this point it would mainly create repetition.

### Why generic animal retaliation is temporary

The release needs food acquisition to have immediate danger, but bespoke cow/pig/sheep/chicken/horse behavior is its own ecology task. The generic response creates the rule now while leaving a clean replacement point for species profiles.

### Why bushes are separate block IDs

Biome identity matters to the project. Alpha 1 already registers one bush ID for each supported terrestrial surface biome. This deliberately costs more registry/data files now so future yield, seasonal, visual, growth, and ecological differences do not require a disruptive ID migration later.

## Assets and licensing

No external resource-pack files are redistributed in this release. Development models use vanilla Minecraft textures.

Research identified MIT-licensed bush-model packs on Modrinth for future curated imports. See `docs/ASSET_SOURCES.md`.

## Validation performed

- every JSON resource in the source tree parsed successfully in the generation environment;
- internal worldgen references were checked for matching configured/placed feature names;
- source tree and release archive were generated successfully;
- Java dependency compilation and a Minecraft client launch were **not available** in the generation environment because Gradle/Fabric dependencies were not locally resolvable.

Therefore the first `gradle runClient` is a required validation gate. Any compile/API mismatch discovered there should be fixed as `0.1.0-alpha.1a` or the next distinct release rather than silently rewriting this historical release.

## Known limitations

- stone-working progress is intentionally in-memory and does not survive logout/restart;
- bush/rock visuals are placeholders;
- bushes currently disappear when harvested rather than becoming a depleted/regrowing state;
- the generic animal retaliation steering may compete with some vanilla panic goals;
- no species-specific animal response exists yet;
- block capability checks are still only the deny-by-default seam; the formal operation API arrives with actual tools;
- world generation needs fresh-world in-game validation.

## Next pressure

Alpha 2 should make Twigs useful. The next complete loop should introduce plant fibers/cordage and the first composite implements while replacing ad-hoc future break permissions with an operation-oriented capability system.
